## 2. How to read the tables

- Tuning and test are strictly separate. **Tuning (Ajuste)** numbers may guide development. **Test (Teste)** numbers must not be used for tuning, thresholds or model selection; they are for reporting only.
- Precision is computed on **annotated loci only**: a called locus counts as true positive if it overlaps a truth region of the called class and as false positive if it overlaps an annotated region of another class. Loci that match no truth region ("unknown") are **not counted as false positives**, so precision is not a measure of novelty or of total false discovery. FDR = 1 - precision.
- Recall = fraction of truth regions of the class hit by at least one locus called in that class (a region counts as hit when any such locus overlaps it by at least `min_overlap_frac` of the locus or of the region, so one locus covering several adjacent regions recalls all of them; precision stays per locus). `recall_expressed` restricts the denominator to truth regions with enough reads in the library BAM (at least 10 alignments, `expressed_min_reads` in `benchmark/config.yaml`); it separates "not expressed in this library" from "not detected". Recall columns use the **primary truth source** of each class (secondary sources are listed separately).
- Precision, FDR, n_called come from the merged-truth classification table (all truth sources of the species together, so cross-class confusions are visible). "Precision (primary source only)" is the same quantity restricted to the primary source; it is trivially high when that source holds one class only.
- Values are mean (min-max) over the libraries of a species (one library: single value). "—" means undefined (no calls or no truth). Precision `0.000 (no truth)` with "—" recall means that no truth of that class exists in the benchmark; it is not a measured failure.
- Primary truth sources per class: fly miRNA MirGeneDB v3.0 (miRBase v23.1 secondary); fly piRNA piRNAclusterDB 2.0 (Srivastav seed secondary); fly siRNA Czech et al. 2008; plants miRNA miRBase v23.1, PHAS and hc-siRNA sRNAanno (rice 24-PHAS also Ono et al. 2018 as secondary); Arabidopsis 21-nt phasiRNA only has seed material (tuning only); Bombyx piRNA Lee et al. 2025; Bombyx and maize miRNA miRBase v23.1.
- Several truth files are algorithmic predictions (sRNAanno, proTRAC-based piRNAclusterDB 2.0 and Lee et al. 2025), so recall against them measures agreement with a published caller (Rosenkranz and Zischler, 2012; Chen et al., 2021), not with curated ground truth. The Ono et al. (2018) table and the Arabidopsis/fly seed sets are tuning-only material. See `benchmark/PROVENANCE.md`.

## 5. Key observations and targets for the ML stage

Facts taken from the tables above.

1. **phasiRNA24 is never called in any plant.** 0 calls in all Arabidopsis, rice and maize libraries, against truth of 79 (Arabidopsis), 908 and 804 (rice, Ono plus sRNAanno, and sRNAanno alone) and 480 (maize) loci. In rice and maize hundreds of loci that match another annotated class are called hcsiRNA (991-1113 per rice library, 480-698 per maize library, 121-133 in Arabidopsis against 28-29k true hcsiRNA calls). This 24-PHAS to hcsiRNA confusion is the main error in the plant classes.
2. **Low-precision classes.** Fly siRNA against Czech et al. (2008): 0.115-0.145 (recall 0.17-0.47, with the lowest value in SRR30544372, which has 303 siRNA calls against 928-980 in the other two). Arabidopsis phasiRNA: 0.219-0.257, because loci called phasiRNA overlap hcsiRNA truth.
3. **miRNA precision is about 1 everywhere; recall is bounded by expression.** Precision 0.947-1.000; recall_expressed is 0.59-0.69 for fly (MirGeneDB), 0.29-0.31 Arabidopsis, 0.27-0.46 maize and 0.30 Bombyx. Rice miRNA recall is very low: 0.055-0.073 (0.160-0.189 expressed).
4. **Fragmentation and tiny loci.** Fly libraries carry 6.6-6.8k loci of at most 100 bp. piRNA clusters are split into about 28-31 fragments per piRNAclusterDB cluster (83-88 per Srivastav seed cluster) with recovered fraction 0.68-0.71 and 12.6 fragments per cluster in Bombyx (0.72 recovered). Plant PHAS and hcsiRNA truth regions are covered by about 2 loci each.
5. **Unknown/unannotated calls are not false positives.** 20-22k fly, 33k Bombyx and 5.6-13.6k plant loci match no truth region and do not enter precision.
6. **Calibration.** ECE is 0.05 (fly), 0.02 (Bombyx), 0.20 (rice), 0.26-0.35 (maize) and 0.36 (Arabidopsis). Ambiguous coverage is 0.55-0.99; it is lowest in rice and maize.

## 6. Caveats

- Czech et al. (2008) loci are coverage-defined and scored by overlap, not by boundaries.
- Bombyx piRNA truth is reduced-confidence (chromosome-level identity filter on the p50ma assembly; no chain).
- Test truth for hcsiRNA and siRNA is missing: precision `0.000` with "—" recall means no truth of that class exists in that source. Rice and maize hc-siRNA sets were built but are not in the repository (size), so hcsiRNA calls in those species are scored only for their effect on other classes. Maize PHAS loci of Zhai et al. (2015) were not obtained.
- Bombyx is a single library, so no replicate range is available for the arthropod test set.
- The aggregate tables are an unweighted mean over the libraries of a species, then over species; each group currently contains one species.
- Tuning libraries are stale (section 1.2) and sRNAanno, proTRAC-based and seed truth are predictions or tuning material (section 2).

## 7. How to reproduce

Environment variables: `BENCHMARK_DATA` (data directory with reads, genomes and work, default `data/benchmark` under the repository) and `SRNAPROFILER_PYTHON` (Python interpreter used to run `srnaprofiler.py`, default the current interpreter). Reads are fetched with `benchmark/scripts/download_reads_sra.sh ACCESSION OUTDIR`; tools are listed in `benchmark/environment.yml`.

```bash
export BENCHMARK_DATA=~/srnaprofiler/data/benchmark
export SRNAPROFILER_PYTHON=/path/to/env/bin/python
python -m benchmark check-manifest
python -m benchmark run --library <ACC> --results-dir <R> --threads N   # one call per library
python -m benchmark report --results-dir <R> --out report.md
```

`python -m benchmark metrics --library <ACC> --results-dir <R>` rebuilds `metrics.json` from an existing work directory (used when only truth files change). A library whose recorded pipeline hash differs from the hash of the checkout that runs `report` is marked stale (tuning) or INVALID (test). Only test libraries with status ok enter the aggregate; tuning libraries never do.
